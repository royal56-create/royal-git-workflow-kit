# Workflow Planner

## Solo project
- Keep the default branch stable.
- Use a short feature branch per change.
- Run tests and review the diff before merging.

## Team project
- Protect the default branch.
- Require pull-request review and CI checks.
- Use issue templates for reproducible reports.
- Agree on merge-versus-rebase policy.

## Release workflow
Select a release commit, run tests, update changelog/version, review tag and release notes, and publish only with maintainer approval. Choose the simplest workflow appropriate to team size and risk.
